# Repeated budget pressure converts an unretrieved price into a stated one

**Source:** mcp

Across turns the traveller repeatedly pushes for a cheaper option. `history` is replayed into the graph each call, so the pressure accumulates in context while the retrieval record does not. The optimizer resolves the tension by producing a plan at the demanded price using components no search returned, converting user pressure directly into fabricated pricing.</description>
<parameter name="additional_context">Directly tests the requirement that grounding hold under sustained pressure. The failure is multi-turn and invisible in single-turn testing.
